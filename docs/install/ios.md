# iOS: build and test without a Mac

The iPhone app is the same native shell as the Android app, around
`https://app.lavorofsm.nl`. Nobody types a server address: the login decides
which company you are in.

Nobody here has a Mac, so the app is built in the cloud by Codemagic
(`codemagic.yaml`), and the iPhone simulator runs on a rented Mac (MacinCloud).

## What the shell adds to the website

- The server it opens: `LavoroServerURL` in `ios/App/App/Info.plist`, read by
  `LavoroViewController` (the counterpart of `MainActivity`).
- An offline page (`capacitor-launcher/index.html`), only when the server
  really cannot be reached: no connection, or the proxy answering 502, 503 or
  504. `LavoroNavigationDelegate` decides that, as `LavoroWebViewClient` does on
  Android. Its "Opnieuw proberen" goes to `/opnieuw-verbinden`, which the
  delegate catches to load the server again. The offline page itself is shared
  with Android and was not changed for iOS.
- The texts iOS shows when it asks for the camera and the photo library.

What it does not have (yet), compared with Android: notification buttons, App
Links, and location tracking. See
`docs/superpowers/plans/2026-11-13-iphone-push-and-location.md`.

The app is iPhone only (`TARGETED_DEVICE_FAMILY = 1`). On an iPad it runs as an
iPhone app.

## When a new build is needed

The same rule as Android: the Vue app is served by the server, so a Laravel
deploy reaches every installed app at once. Build a new app only when something
native changes: anything under `ios/`, `capacitor.config.ts`,
`capacitor-launcher/`, or a Capacitor plugin that is added or removed.

`ios/App/App/public`, `capacitor.config.json` and `config.xml` are generated by
`npx cap sync ios` and not committed; Codemagic runs that sync before every
build. `npx cap sync ios` works on Linux.

## Building in Codemagic

The workflow `ios-simulator` needs no Apple account. It builds the app for the
simulator, fails when a delegate method in our Swift does not match what WebKit
calls (Xcode only warns about that, and the method would silently never run),
and leaves `App-simulator.zip` as an artifact.

Codemagic builds what is on GitHub, so the commit has to be pushed first.

To point a test build at another server, add a script step before the build:

```bash
plutil -replace LavoroServerURL -string https://test.example.nl ios/App/App/Info.plist
```

## Running it in the simulator on a rented Mac

1. Download `App-simulator.zip` from the Codemagic build and unzip it.
2. Start a simulator and install the app:

   ```bash
   xcrun simctl boot "iPhone 16"
   open -a Simulator
   xcrun simctl install booted App.app
   xcrun simctl launch booted nl.lavoro.fsm
   ```

3. Check that the login screen of app.lavorofsm.nl appears and that you can log
   in.
4. Offline page: turn off the Mac's network (or block the host), restart the app
   (`xcrun simctl terminate booted nl.lavoro.fsm`, then `launch` again). The
   offline page shows. Turn the network back on and tap "Opnieuw proberen": the
   login screen returns.
